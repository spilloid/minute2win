# MCP and account validation

Pre-publication validation of 0.6.0. Tested on Windows with Go 1.27.4, Python
3.13, MCP Python SDK 1.30.0, Playwright 1.55.0 and installed Chrome. Tests used
temporary profiles/state, loopback HTTP, synthetic MACs and no PXE service.
No physical machine was armed or installed by these checks.

## Passed checks

- Native server vet and full race suite; targeted race checks after follow-up
  changes. Companion vet and full race suite. Server cross-builds for Linux
  amd64/arm64 and Windows amd64 with cgo disabled.
- JSON-RPC initialization/negotiation, discovery, resources, prompts, malformed
  requests, argument schemas, authentication and cross-origin refusals.
  Real MCP SDK HTTP and stdio connections to the same existing host pass.
- Persistent arming request receipts retain run IDs and cannot re-arm after
  consumption, disarm or restart. Conflicting request parameters are rejected.
  Monitoring distinguishes pending, running, terminal, stale and mismatched
  runs; snapshots omit report keys and boot tickets.
- Local accounts, hashed passwords/tokens, one-login repeated arming, logout,
  exact image scopes across MCP/API/console, policy-change credential revocation
  and rollback after failed account/configuration saves.
- Signed TLS mock OIDC with S256 PKCE, browser-bound state, nonce, issuer,
  audience, signature, expiry and group-type checks. Group roles and immutable
  subject overrides pass. Noncanonical login redirects before issuing cookies;
  public PKCE clients send client_id parameters without empty Basic credentials.
- Confined media import/inspection and HTTPS fixture downloads: matched pins,
  mismatch, byte limits, access refusal, downgrade redirect, cancellation,
  no overwrite and partial cleanup. Job IDs can be recovered by listing.
  Hashing/pin matching does not authenticate the publisher.
- Explicit stopped-target tracking recovery revokes delivery/report capabilities,
  records outcome unknown and unblocks configuration without claiming remote
  cancellation or installation success.
- Browser checks at 1280 px/light and 390 px/dark: one login, two arms without
  another credential, disarm, logout, viewer restrictions and no horizontal
  overflow. Existing synthetic boot/report/timing/phone checks pass. Desktop
  login and signed-in phone captures were visually inspected.
- Kustomize rendering of Authentik, unchanged production minute2win and the
  inactive MCP/OIDC component. Static assertions cover callback/grant, blueprint
  registration, no plaintext client secret, role/image mapping, control-only
  ingress, counts-only telemetry, managed mount permissions and the existing
  non-root/single-writer/capability policy. Wildcard cloudflared routing already
  covers the new hostname; no tunnel change was required.
- Site-version and diff whitespace checks; Python integration scripts compile.

## Findings resolved

The first full race run found a new fixture persisting the old reserved
`img.example` base. Configuration reload correctly refused it; the fixture now
uses `boot.lab.internal`, and the corrected full suite passes. An early SDK
assertion expected more tools than the initial registry; the final registry has
28 tools and both SDK transports pass. Final review also added a regression
preventing an overlapping profile/data root from exposing state, report keys
or account hashes as a readable profile.

The companion now reads anonymous `/api/status` counts, with a legacy fallback
only after 404, so it does not need authenticated deployment details. Native
SSO uses Secure/HttpOnly/Lax cookies for the IdP return redirect; local sessions
remain Strict. Existing cross-origin mutation protection remains in force.

## Limits and release gates

- No deployment to the live host or real `auth.spillerstech.us` tenant. The
  Homelab provider and rollout component are source changes. Production does
  not activate the component before explicitly pinning a tested new image.
- No new VM/physical install, firmware interaction, ADK build, external upload,
  Secure Boot check or installed-desktop verification. Power and console
  actions remain separate tools. Windows licensing/consent, ISO extraction,
  WinPE building and external hosting are guided host/service tasks.
- Real Authentik sign-in, DNS, certificates and ingress require rollout checks.
  IdP group changes apply at next login within the one-hour SSO session limit;
  no back-channel logout or group polling is implemented.
- Media jobs are process-local. Persistent arm receipts require persistent
  state. PXE start/stop is process-local; explicit startup flags override saved
  image-base/Linux-root/TTL settings.
- The unchanged release-workflow mock harness passed its allowlist cases but
  could not complete the POSIX mock-gh phase under native Windows/Git Bash.
  It remains a Linux CI check. Full CI, container publication, signing and
  packaged-artifact verification have not run for this candidate.
- Independent release review was completed on 2026-11-15. It found a pending-arm
  replacement scope bypass, reproduced against the API before fixing the shared
  operation. API/UI/MCP regression checks now preserve the old image and ticket
  on refusal, while allowing authorized and expired-arm replacements. The
  reviewer confirmed closure with no additional blocking findings. Native
  targeted race checks pass; hosted CI remains the publication gate.

These checks expand package/control-plane evidence. They do not establish fresh

broad physical hardware coverage, graphical macOS/Linux tray behavior or macOS
Developer ID/notarization. Those gaps remain explicit. The separate Homelab
rollout was not activated by publishing this release. Further evidence will be
appended with its version/date/environment; artifact fixes require a patch.
